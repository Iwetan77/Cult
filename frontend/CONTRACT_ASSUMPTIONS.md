# Frontend-only assumptions

Status (2026-09-28): I reconciled the mainnet funding and trading changes against `origin/backend:CONTRACTS.md` at `e69df06`. This file records only frontend choices and remaining gaps. Dollar values render with `$`; deposit token names and wallet setup action labels come from the backend.

- Direct AUSD deposit means sending AUSD on the configured Monad chain to the member's own embedded-wallet address, then continuing the member-signed Perpl setup. The backend has no separate direct-deposit endpoint. The UI shows backend Perpl margin separately from wallet dollars, falling back to `collateralBalance` only when balances are unavailable.
- The backend `/v1/me.balances` is authoritative for wallet dollars, Perpl margin, MON value, gas reserve, and whether Nad.fun buys spend wallet dollars or MON. A testnet RPC MON read remains a fallback when balances are unavailable. The backend enforces funds and gas limits; its current reserve is 0.25 MON, and the UI reads `gasReserveMon`.
- Trading permission applies to everyone. Own trades and manual stacks request `GET /v1/privy/signer` plus `addSigners` whenever `attached` or `policyCurrent` is not true, then verify the refreshed account before submitting. Deposit offers the same permission for automatic USDC conversion. Joining alone still does not request permission.
- Deposit renders `GET /v1/wallet/deposit.tokens`, including Circle testnet USDC as read-only wallet visibility. `depositSupported=false` excludes a token from send instructions, dollar totals, and Cult withdrawal choices; older backend responses without the flag remain compatible. Testnet USDC is not converted or usable for trades, and testnet MON cannot fund perps through a swap. A null token balance displays as unavailable, never zero. The backend supplies token descriptions, balances, and the network name. Mainnet automatic USDC conversion and trading top-ups are handled by the backend.
- Privy's default chain follows `NEXT_PUBLIC_MONAD_CHAIN_ID`: 143 selects mainnet; 10143 or an unset value selects testnet. Wallet setup and transaction receipt checks follow `config.chainId`. Setup actions run in their returned order with a receipt awaited for each.
- `usdcConverted.at` is a millisecond timestamp. The most recently shown timestamp is stored per member to avoid repeated conversion toasts; visible sessions refresh account data every 20 seconds, stopping that poll on a 429 response.
- A mirror retry error exists in the authenticated SSE `mirror` event, not in `ChartMarker`. The frontend displays it while the matching marker remains pending and re-fetches the chart for its new skip deadline.
- Chart markers and Nad.fun values are already dollar-denominated in the backend payload, converted from MON with its served price. The frontend does not convert them again. Null PnL, ROI, holdings, and unverified indexer track records stay empty or pending.
- A member's headline record counts only their own indexed round trips. Copied round trips display separately, and venue PnL keeps Perpl in dollars and Nad.fun in MON; null win rate displays as a dash rather than zero.
- Perpl TP/SL guides use the published nullable trigger prices. An unset leg has a draggable handle at the marker entry but no guide line; dragging previews a draft, then the owner updates `/v1/positions/tpsl` or a clan-mate submits `/suggest-tpsl`. Nad.fun has no guides. Suggestions stay advisory until the owner applies one.
- The authenticated clan SSE stream refreshes chart snapshots on trade, trade_changed, mirror, adjustment, and suggestion events; a 30-second poll remains as a fallback. The skip countdown uses each marker deadline and the config-provided opt-out window, never a hard-coded duration. A pending add uses its own `adjust:` id and deadline; partial reductions never show a skip.
- Clan chat bodies render as plain text. A chat marker link only carries `markerId`, not `marketId`; when the marker is not on the current chart, the frontend checks the clan markets one at a time and reports if it is no longer open.
- A 429 response uses the CORS-exposed `Retry-After` seconds in its message; the frontend never retries order or chat submissions automatically. A 429 on the SSE stream stops its reconnect loop, while chart polling remains a fallback.
- The public share UI shows `clanName` only when `includeClan` is true. The backend's public endpoint must continue omitting the clan ID, invite code, and member list regardless of UI choice.
- Cult is the UI term; JSON names such as `clanId` and `clans` remain unchanged. The frontend calls canonical `/v1/cults` routes. Invite input normalizes six letters to `ABC-DEF`, while existing legacy invite codes may still be displayed as returned.
- Account shows country as read-only; there is no country picker or edit button. Server-side location enforcement is pending explicit approval for IP-country lookup.
- The navigation uses `/v1/me.rooms` for Global and country chat. Cult chat uses the same room-message API but relies on the Cult chart SSE stream; other rooms open their own authenticated room SSE connection.
- Discover lists public Cults with one-tap unsigned joining. A new Cult also starts with copying off. The member signs limits only when turning on Auto-follow; turning it off is instant. Ranking screens show own-trade results, list copied counts separately, and pin the member's row even when unranked.
- Auto-follow copy limits belong to the member in each cult (`Clan.myPolicy`). The editor preserves saved limits when copying is off and uses `config.autoFollowDefaults` only without a saved policy. Exact numeric inputs accept the published ranges: `maxUsdPerTrade` from $1 to $1,000,000 and `balancePercentCap` above 0% through 100%, including fractional values. Enabling or editing still signs `/policy/challenge` then submits `/policy`; signer approval is refreshed when required.
- Auto-follow shows Perpl copy readiness separately from Privy signer permission: account creation, enrolled trading key, and forwarding must all be complete. Enabling copying does not silently sign those steps. Group details offer the member-signed setup action and surface only the current member's failed/cancelled mirror or adjustment reason from SSE. Old failed trades are not replayed after setup.
- Chart members now include `owner`, derived by the backend from immutable cult creation ownership. The creator is labelled Owner; no role-management control is offered for them. Only the owner can add or remove admins; ordinary admins keep trade-sharing permissions but never see role-management controls. The API enforces the same restriction on both `/v1/cults` and legacy `/v1/clans` routes. Testnet perp tickets exclude MON and testnet USDC from available margin, matching backend funding limits; mainnet conversion remains supported.
- Copy limits are caps, not a fixed personal spend or a total cult budget. The engine uses the leader's balance share against the follower's free venue balance, capped by the member's percentage; perp leverage then gives notional, capped by the dollar limit. On memes the percentage caps spendable wallet funds. Each leader add has the same caps per add. Editing limits does not resize existing positions. Cult Settings links to the same personal limit editor, and changing rooms discards its draft.
- Room activity subtitles come from `/v1/me.rooms.lastMessage`; the chat renders system notices as plain text and owner pins via `/v1/chat/:room/pin`.
